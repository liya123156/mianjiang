本次前端继续发布在原 GitHub Pages 地址。共享服务尚未连接，页面明确标示归档快照和连接状态；未把当前浏览器记录冒充共享数据。

## 页面

- 日常推动：按月、全司／大区／单店筛选，17字段进展表、图片导出、规则预警、标杆鼓励、可复制微信话术、现场补充和推动动作。
- 项目计划、周／月复盘：保留原页面、历史归档、11月计划和候选房源下探。
- 费用核账：单店月账、采购凭证复用、整数分币分摊、实际收款／返还／公司到账、上月余额结转、锁账与解锁原因。
- 数据管理：负责人同时选择底表与面见明细，预览截止日及汇总后提交。当前底表覆盖、事件去重，快照和BP记录单独保留。

## 一次性连接

1. 在自己的 Supabase 项目 SQL Editor 依次执行 `database-setup.sql`、`database-upgrade.sql`。
2. 在 Authentication 中开通负责人及BP账号。账号创建与首次密码由账号所有人完成；不要在聊天或仓库中粘贴密码、secret/service_role key。
3. 在 `wb_members` 中配置实际登录邮箱、角色和负责范围。`project` 是负责人，`region` 是单大区，`store` 是单店或多店BP。多店BP的主门店填 region/store，额外门店填 stores，例如 `[{"region":"花木大区","store":"碧云店"}]`。
4. 把项目 URL 和公开 publishable/anon key 填入 `operations/cloud-config.js`，通过 GitHub 发布。公开 key 的权限由数据库 RLS 限制，绝不使用管理员密钥。
5. 负责人登录原链接，进入数据管理，导入一组真实数据；用BP账号在另一个浏览器验证仅能读取授权组织、记录刷新后仍保留，再开放协作。

数据库和凭证匿名不可读；原来已公开的复盘归档仍按原链接展示。首次开通共享服务不会自动创建账号或迁移底表。

## 核账口径

- 新导入数据不会修改费用、现场补充、动作、规则或实际收付款。
- 房源按月份去重；已有费用房源跨店再次登记会被数据库拒绝。下架或取消底表送礼标记后，已保存的本月费用仍保留。
- 规则按月份和单店确认。历史月份的注入额必须按实际填写，100元、150元等均可；未确认规则不能锁账。
- 店总池／大区池期初、应注入、耗用和分摊后应结余分别计算。实际到账和返还另行登记，抵扣剩余应收付；结账不等于实际款项已付清。
- 锁账保留当时的明细、规则和结余。调整需负责人填原因解锁；历史审计记录保留。
- 目前预警和鼓励是数据规则与文案模板，大模型服务尚未接入。周／月复盘保留已发布归档，不将其静默改写为最新日报。
