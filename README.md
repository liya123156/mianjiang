# 在售业主面见 · 计划与复盘工作台

同一工作台按月留存项目目标、行动计划与结果复盘，并支持全司、大区和门店范围。

## 月份与内容

- **2026年10月**：现有复盘及内嵌Word原样保留，数据截至10月25日；“项目计划”归档现有目标和10月27—31日冲刺安排，月初原始方案待补充。
- **2026年11月**：感恩月方案初稿，包含总目标、三个子目标与关键支撑、全月行动、角色职责、贺卡/模板和待共识事项。目标套数、预算与采购款尚未确认；实际结果未录入。

入口示例：

- `?month=2026-10&tab=review`：10月结果复盘。
- `?month=2026-10&tab=plan`：10月计划归档。
- `?month=2026-11&tab=plan`：11月感恩月项目计划。

原有`region`、`store`参数继续适用。页面支持复制分享链接、复制当前文本、打印/保存PDF；10月保留进展图片与Word下载。

## 维护位置

- `index.html`：原复盘数据与交互，内嵌Word。
- `project-plan.js`：11月方案内容、计划视图及月份衔接。计划与实际数据分开；以后录入11月实际数据时，补充该月`views`并移除`planOnly`标记。
- `project-plan.css`：计划页样式，含手机与打印布局。
- `assets/gratitude-*.webp`：三款感恩贺卡底稿。

这是按月展示与分享的工作台。执行状态目前为方案中的排期标记；尚未接入系统自动同步或多人在线编辑。

## 2026-11-04 · 感恩月规划与执行闭环

主链接默认打开11月项目规划；10月与历史归档按原月份保留。

- 项目规划：完整总目标常显，四项核心策略展开35项动作，包含做法、角色、排期、验收与业务关联。建议日期与已知完成事实分开。
- 日常推动：35项明细按实际承接合并为24类任务模板，以同一行动编号关联；按门店/大区/全司和日期预生成整个周期。默认新节奏从11月5日起执行，可切换日期查看。
- 单店检核：BP记录结果、依据、店组行动、问题和正反馈；提交后进入待验收，大区BP或项目负责人确认通过/退回。每次记录由服务端追加留存。
- 周复盘：按到期日汇总执行结果，任务验收率与业务目标达成率分开。业务底表继续在数据管理统一导入。
- 费用核销：沿用既有礼品费用分摊、凭证、实际收付款和报销核对，不修改旧计算逻辑。

### 共享执行与组织授权

`shared-setup/database-plan-execution.sql` 添加独立任务表和会话鉴权RPC；费用及旧 `wb_items` 不受影响。先应用该SQL，再应用初始化SQL，最后发布页面。

规划无需登录；实际任务及历史只对已有授权范围开放。任务在发布时按全周期预排，无需每天打开网页才能生成。重复发布只补齐缺少任务，不覆盖BP结果。站内任务不等于企业微信或邮件通知。

21店初始范围来自系统已有组织名册（2026-10-27）。其中名册“徐汇二店”与业务明细“徐汇一店”的名称差异需在组织口径核对时确认，不自动合并。BP姓名、工号和负责范围必须经项目负责人确认后配置到既有成员授权表；未配置的店/大区任务显示待分派，不能凭店名推断授权人。

服务端只允许责任范围内提交；店面BP不能自行验收，验收人和时间由服务器记录。已生成任务保留当时的动作快照，已有排期不随模板修改而无声变化。
